# 🐳 Essential Docker Cheat Sheet

Welcome to your comprehensive guide for navigating and managing Docker containers, images, and system states efficiently.

---

## 1. Checking Status & System Info

* **`docker version`**
  * **What it does:** Displays the current version of the Docker client and daemon installed on your system.
* **`docker info`**
  * **What it does:** Provides a detailed system-wide overview, showing how many containers and images you have, storage drivers, CPU/memory limits, and system configurations.

---

## 2. Managing Images (The Blueprints)

* **`docker pull <image_name>`**
  * **What it does:** Downloads a Docker image (e.g., `ubuntu`, `nginx`, `postgres`) from the Docker Hub registry to your local machine without running it.
* **`docker images`**
  * **What it does:** Lists all Docker images currently downloaded and stored locally on your machine, along with their tags, image IDs, and sizes.
* **`docker rmi <image_id_or_name>`**
  * **What it does:** Deletes/removes a local Docker image from your system to free up storage. *(Note: You must stop and remove any containers using that image first).*

---

## 3. Running & Managing Containers (The Instances)

* **`docker run <image_name>`**
  * **What it does:** Creates and starts a new container from a specified image. By default, it runs in the foreground.
* **`docker run -d -p <host_port>:<container_port> --name <custom_name> <image_name>`**
  * **What it does:** Runs a container professionally in **detached mode** (`-d` for background execution), maps a port from your machine to the container (`-p`), and assigns it a custom readable name (`--name`).
* **`docker ps`**
  * **What it does:** Lists all **currently running** containers. 
* **`docker ps -a`**
  * **What it does:** Lists **all** containers on your system—both running and stopped/exited ones.
* **`docker stop <container_id_or_name>`**
  * **What it does:** Gracefully stops a running container by sending a SIGTERM signal, giving it time to shut down safely.
* **`docker start <container_id_or_name>`**
  * **What it does:** Starts an existing, stopped container back up.
* **`docker restart <container_id_or_name>`**
  * **What it does:** Restarts a running or stopped container.
* **`docker rm <container_id_or_name>`**
  * **What it does:** Deletes a stopped container from your system. (Add the `-f` flag—e.g., `docker rm -f`—to force-delete a container that is currently running).

---

## 4. Interacting with Containers

* **`docker logs <container_id_or_name>`**
  * **What it does:** Fetches and displays the console output/logs generated by a container. (Add `-f` to follow logs in real time as they happen).
* **`docker exec -it <container_id_or_name> <shell>`**
  * **What it does:** Opens an **interactive terminal session** (`-i` for interactive, `-t` for tty) inside a running container (e.g., running `docker exec -it my_container bash` lets you step inside the container's file system).
* **`docker cp <source> <destination>`**
  * **What it does:** Copies files or folders back and forth between your local host machine and a container (e.g., `docker cp myfile.txt my_container:/app/`).

---

## 5. Cleanup & Maintenance

* **`docker system prune`**
  * **What it does:** Cleans up unused data by removing all stopped containers, dangling images, unused networks, and build caches to recover disk space. (Use with `-a` to remove all unused images, not just dangling ones).
